# Output Template A · Claude 스킬 (`SKILL.md`)

**언제 사용**: Step 5에서 사용자가 **A. Claude 스킬** 형태를 선택했을 때.

**왜 A를 선택?** — 글/문서를 인터뷰·정리·생성하는 부품. 가장 가볍고, 인터뷰 끝과 동시에 사용 시작.

---

## Step 6 추가 질문 (Q 톤, 발판형, 5~7분)

다음 5개 항목을 빠르게 채워주세요. 각 답은 1~3문장이면 충분.

### 1. 한 줄 정체성

**질문**:
> "이 스킬을 한 줄로 요약하면? '[누구]가 [언제] 발동하면 [무엇]을 만들어주는 스킬'."

**발판** (사용자가 막힐 때):
> "예: '마케터가 신규 클라이언트 미팅 직후 발동하면 1페이지 브리프를 만들어주는 스킬', '나 자신이 일요일 저녁 회고할 때 발동하면 한 주 카드를 만들어주는 스킬'"

### 2. 트리거 키워드 3~5개

**질문**:
> "Claude 메시지에 어떤 단어가 들어오면 이 스킬이 자동으로 발동해야 할까요? 3~5개 적어주세요."

**발판**:
> "예: '클라이언트 브리프', '신규 미팅 정리', '한 주 회고', '일요일 회고'"

### 3. 인터뷰 단계 (3~6단계)

**질문**:
> "이 스킬이 사용자에게 몇 단계로 흐를까요? 각 단계의 한 줄 목적만 적어주세요."

**발판**:
> "예 — 1. 워밍업 / 2. 맥락 파악 / 3. 핵심 발굴 / 4. 정리 출력"

### 4. 각 단계의 핵심 질문 1개씩

**질문**:
> "각 단계에서 사용자에게 던질 핵심 질문 1개씩. 막연하지 말고 구체적으로."

**발판**:
> "✅ 좋은 예: '최근 한 달간 가장 많은 시간을 쓴 업무 1개를 알려주세요. 그 업무를 한 줄로 묘사한다면?'"
> "❌ 안 좋은 예: '당신의 업무에 대해 알려주세요'"

### 5. 최종 출력 형식

**질문**:
> "인터뷰가 끝났을 때 손에 남는 결과물의 모양은? 1페이지 마크다운? 표? 체크리스트?"

**발판**:
> "예: '1페이지 마크다운 — 비즈니스 한 줄, 페르소나, 진짜 문제, 다음 액션'"

## 결과물 — `<skill-name>.skill.md`

답이 모이면 다음 형식의 한 파일로 출력됩니다.

```markdown
---
name: <부품 이름 - 영문 소문자, 하이픈 사용>
description: <답 1을 압축한 트리거 설명. "사용자가 ___을 언급할 때 발동하여 ___을 만든다" 형태>
---

# <부품 이름> 🎤

<2~3줄 소개>

## When to use this skill

자동 발동 트리거:
- <답 2의 키워드 리스트>

발동 안 해야 할 상황:
- <Claude가 추론해서 채움>

## How this skill works

<답 3의 단계 풀어쓰기>

### Step 1 · <단계 이름>
<목적 + 답 4의 질문 1>

### Step 2 · <단계 이름>
<목적 + 답 4의 질문 2>

...

## Harness rules

(인터뷰 도중 사용자가 추상적으로 빠질 때 잡아당기는 규칙 — Claude가 부품 성격에 맞게 2~3개 자동 생성)

## Output format

<답 5에 맞춰 출력 양식 채움>
```

---

## 사용 방법

```bash
# 1. 결과물 파일을 ~/.claude/skills/ 로 옮기기
mkdir -p ~/.claude/skills/<부품-이름>
mv <부품-이름>.skill.md ~/.claude/skills/<부품-이름>/SKILL.md

# 2. Claude 재시작 (또는 새 세션)
# 3. 트리거 키워드 던지면 자동 발동 확인
```

✅ **인터뷰 끝 = 사용 가능**. 이게 A 형태의 가장 큰 장점.

---

## 다듬기 팁 (스킬 발동 후)

- 첫 발동 시 어색한 단계 발견되면 SKILL.md 직접 수정 (편집기로 열어서 한 줄 고치고 저장)
- 트리거가 너무 좁으면 키워드 추가, 너무 넓으면 description 보강
- 단계 4의 질문이 답을 산으로 보내면 더 좁힌 표현으로 다시
