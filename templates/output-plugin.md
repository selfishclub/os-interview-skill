# Output Template B · Claude Code 플러그인

**언제 사용**: Step 5에서 사용자가 **B. Claude Code 플러그인** 형태를 선택했을 때.

**왜 B를 선택?** — 터미널 워크플로우, slash 커맨드, 자동 트리거(훅), 외부 API 연동(MCP)이 필요. A(스킬) 한 개로는 안 되고 여러 컴포넌트의 묶음이 필요할 때.

> ⚠️ B는 가장 무거운 형태입니다. 처음에는 **A부터** 시도하고, 스킬이 여러 개로 늘어나거나 커맨드/훅/MCP 연동이 필요해지면 그때 B로 묶는 것이 일반적입니다.

---

## Step 6 추가 질문 (Q 톤, 발판형, 7~10분)

플러그인은 **여러 컴포넌트의 묶음**입니다. 다음 6개 항목을 채워주세요.

### 1. 한 줄 정체성

**질문**:
> "이 플러그인을 한 줄로 — '[무엇]을 [어떻게] 자동으로 처리해주는 Claude Code 플러그인'."

**발판**:
> "예: '매일 아침 캘린더+미답 메일+어제 회고를 한 화면에 모아주는 데일리 브리핑 플러그인'"

### 2. 포함될 컴포넌트 (있는 것만 체크)

**질문**:
> "다음 중 무엇이 포함되어야 하나요? 여러 개 선택 가능."

- [ ] **slash 커맨드** — `/<이름>`으로 직접 호출 (예: `/morning-brief`, `/wrap-session`)
- [ ] **훅(hook)** — 특정 이벤트 시 자동 실행 (예: SessionStart, ToolUse 직후)
- [ ] **스킬(skill)** — 키워드 자동 트리거 (A 형태와 동일, 플러그인 안에 묶음)
- [ ] **MCP 서버** — 외부 시스템 연결 (예: Notion, Google Calendar, Linear)

**발판**:
> "체크가 1개뿐이면 사실 A(스킬) 또는 단일 커맨드로 충분할 수 있어요. B는 보통 2개 이상 묶여요."

### 3. 각 컴포넌트의 역할 한 줄씩

**질문**:
> "체크한 컴포넌트마다 무슨 일을 하는지 한 줄."

**발판**:
> "예:
> - 커맨드 `/morning`: 오늘 캘린더 + 미답 메일 + 어제 회고를 한 화면에 정리
> - 훅 `SessionStart`: Claude Code 켤 때 어제 작업 요약 자동 표시
> - MCP 서버 `notion`: 정리 결과를 Notion 페이지로 저장"

### 4. 사용자 입력

**질문**:
> "각 컴포넌트가 무엇을 받나요? 인자, 환경변수, 파일 등."

**발판**:
> "예: 커맨드는 `날짜`(인자), 훅은 자동(입력 없음), MCP는 `NOTION_API_KEY`(환경변수)"

### 5. 출력 / 부수효과

**질문**:
> "사용 후 무엇이 바뀌나요? 파일 생성? Slack 알림? Notion 페이지?"

### 6. 외부 의존

**질문**:
> "사용자가 미리 준비해야 할 것이 있나요? API 키, 다른 도구 설치 등."

**발판**:
> "예: Notion API 토큰, Google Calendar OAuth, gh CLI 설치"

## 결과물 — 플러그인 폴더 구조

답이 모이면 다음 폴더 구조로 출력됩니다 (체크한 컴포넌트만 생성):

```
<plugin-name>/
├── plugin.json              # 메타데이터 (이름, 버전, 컴포넌트 등록, 의존성)
├── README.md                # 설치/사용법 안내
├── commands/                # 체크한 경우만
│   └── <command-name>.md
├── hooks/                   # 체크한 경우만
│   └── <hook-name>.md
├── skills/                  # 체크한 경우만
│   └── <skill-name>/SKILL.md
└── mcp/                     # 체크한 경우만
    └── server.json
```

각 파일의 본문은 Claude가 답 3~6을 기반으로 채워줍니다.

> 📚 파일 양식의 정확한 스펙은 https://docs.claude.com 의 "Claude Code Plugins" 문서를 참조하세요. 이 출력은 v0.1 초안이며, 실제 동작 검증은 사용자가 직접 진행해야 합니다.

---

## 사용 방법

```bash
# 1. 결과물 폴더를 ~/.claude/plugins/ 로 옮기기
mkdir -p ~/.claude/plugins
mv <plugin-name> ~/.claude/plugins/

# 2. 외부 의존(답 6) 설정
# - 환경변수: ~/.zshrc 또는 ~/.bashrc 에 export
# - API 키: ~/.claude/plugins/<plugin-name>/.env 에 저장

# 3. Claude Code 재시작 → 플러그인 자동 로드
```

## 다듬기 팁

- **플러그인은 한 번에 다 만들지 말 것**. 컴포넌트 1개부터 발동시키고, 작동하면 다음 컴포넌트 추가.
- **MCP 서버**는 가장 무겁습니다. 처음에는 커맨드 + 훅으로만 시작하고, 외부 API 연동은 다음 인터뷰에서 확장.
- 컴포넌트별로 작은 스킬을 먼저 만들어보고 그게 안정되면 플러그인으로 묶는 게 안정적입니다 (= 다음 인터뷰에서 A 여러 개 → 그다음 인터뷰에서 B로 통합).
