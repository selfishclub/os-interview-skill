# Output Template C · 독립 프로덕트 PRD

**언제 사용**: Step 5에서 사용자가 **C. 독립 프로덕트** 형태를 선택했을 때.

**왜 C를 선택?** — Claude를 안 쓰는 사람도 써야 하거나, 모바일/웹/공유 가능한 URL 형태가 필요하거나, Claude 환경 밖에서 돌아가야 함.

> 💡 C는 시작점이지 끝이 아닙니다. PRD는 **Claude Code에 던질 입력 문서**이고, 그 뒤에 실제 코드 생성 단계가 따라옵니다.

---

## Step 6 추가 질문 (Q 톤, 발판형, 10~15분)

C는 가장 자세한 출력이 필요합니다. 다음 8개 항목을 채워주세요.

### 1. 한 줄 정체성

**질문**:
> "이 프로덕트를 한 줄로 — '[누구]를 위한 [무엇]을 [어떻게] 해주는 [형태]'."

**발판**:
> "예: '1인 마케터를 위한 클라이언트 미팅 후 24시간 이내 자동 브리프 생성기 (웹앱)'"

### 2. 타겟 사용자 페르소나

**질문**:
> "누가, 언제, 왜 쓰나요? 페르소나 한 명 묘사해주세요. 가상 인물이어도 OK."

**발판**:
> "예: '30대 후반 1인 마케팅 컨설턴트. 주 3건의 신규 미팅 후 48시간 내에 클라이언트에게 브리프를 보내야 함. 지금은 구글 닥스를 매번 처음부터 작성하는데 시간이 오래 걸림.'"

### 3. 핵심 기능 3~5개

**질문**:
> "이 프로덕트의 핵심 기능 3~5개. 각 기능 한 줄로."

**발판**:
> "예:
> 1. 미팅 녹음 업로드 → 자동 트랜스크립트
> 2. 트랜스크립트 → 구조화된 브리프 초안 생성 (페르소나, 문제, 예산)
> 3. 브리프 편집·승인
> 4. PDF 내보내기 / 공유 링크"

### 4. MVP 스코프 (1주 안 만들 것)

**질문**:
> "위 기능 중 처음 1주에 만들 **1개**만 골라주세요. 나머지는 v1.1로."

**발판**:
> "MVP는 보통 입력→가장 가치 있는 출력 1개의 흐름. 위 예라면 '트랜스크립트 → 브리프 초안' 1개부터."

### 5. 기술 스택 (선호)

**질문**:
> "선호하는 기술 스택이 있나요? 없으면 'Claude 추천'으로 비워두세요."

**발판**:
> "예: 'Next.js + Supabase + OpenAI API', 또는 'Python CLI + SQLite', 또는 '비워두기'"

### 6. 인증 & 저장

**질문**:
> "사용자 로그인 필요? 데이터는 어디 저장? (로컬 파일 / 클라우드 DB / 외부 서비스)"

**발판**:
> "MVP에선 보통 인증 없이 + 로컬 저장이 빠름. 다중 사용자 / 디바이스 간 동기화가 필요할 때 클라우드 DB."

### 7. 첫 검증 방법

**질문**:
> "만들어진 직후 어떻게 '잘 됐는지' 확인할 건가요? 누구한테, 무엇으로?"

**발판**:
> "예: '다음 주 본인 미팅 1건에 직접 사용 → 30분 안에 브리프 초안 나오면 성공'"

### 8. 확장 방향 (선택)

**질문**:
> "v2.0에 추가될 만한 것이 있다면 1~2개. 없으면 비워두세요."

## 결과물 — `<product-name>.prd.md`

답이 모이면 다음 형식의 PRD가 출력됩니다.

```markdown
# <Product Name> · PRD draft

**Status**: v0.1 (MVP scope)
**Author**: <사용자 이름>
**Date**: <YYYY-MM-DD>

## Why (이 프로덕트가 존재하는 이유)

<Phase 1에서 끌어낸 통점 + 이상향을 압축. OS 청사진의 통점·이상향 섹션을 그대로 인용해도 OK.>

## Who (타겟 사용자)

<답 2 - 페르소나>

## What (핵심 기능)

<답 3 - 기능 리스트>

## MVP Scope (1주 내 출시)

<답 4 - 골라낸 1개 기능 + 그 기능을 둘러싼 최소한의 골격>

## Tech Stack

<답 5 - 선호 또는 Claude의 추천>

## Auth & Storage

<답 6>

## Validation Plan

<답 7 - 첫 검증>

## Future (v2.0+)

<답 8>

---

## 🤖 Implementation prompt for Claude Code

> 이 PRD를 읽고 MVP 스코프부터 구현해줘.
> 1. 폴더 구조부터 잡고
> 2. 가장 작은 동작 가능한 슬라이스를 먼저 (E2E 한 줄 흐름)
> 3. 그게 굴러가면 핵심 기능 1개를 완성
> 4. 마지막에 README.md와 실행 방법 정리
>
> 의문이 있는 지점은 묻고 진행해. PRD를 수정해야 할 부분이 보이면 제안해줘.
```

---

## 사용 방법

```bash
# 1. 새 작업 폴더 만들고 PRD 옮기기
mkdir -p ~/Documents/<product-name>
cd ~/Documents/<product-name>
mv ~/path/to/<product-name>.prd.md ./PRD.md

# 2. Claude Code 켜기
claude

# 3. 첫 프롬프트
# "PRD.md를 읽고 MVP 스코프부터 구현해줘. 폴더 구조부터 잡고,
#  첫 단계로 무엇을 만들지 제안한 다음 진행해."
```

## 다듬기 팁

- **PRD는 시작점**, 끝이 아닙니다. 구현하면서 PRD도 같이 업데이트하세요 (`PRD.md`를 git으로 관리하면 변경 이력도 남음).
- MVP 스코프가 1주 안 안 끝나면 **스코프가 너무 큰 것**. Claude Code에게 "이 MVP를 절반으로 줄이려면 어디를 잘라야 할까?" 물어보세요.
- **검증 단계(답 7)를 가장 먼저 세팅**. "만들고 나서 어떻게 확인할까"를 정해두지 않으면 만든 다음에 표류합니다.
- 이 부품이 완성되면 OS 청사진의 부품 후보 리스트로 돌아가서 다음 부품을 결정. 두 번째 인터뷰부터는 Phase 1을 짧게(이미 청사진이 있으니) 갈 수 있어요.
